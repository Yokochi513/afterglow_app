# 09. プロフィール

## 1. 概要

ユーザーのプロフィール画像・ユーザー名・自己紹介と、その人の投稿一覧を表示する。自分のプロフィールでは編集とログアウトができる。他人のプロフィールは閲覧のみである。

| 項目 | 内容 |
|---|---|
| 関連要件 | FR_06（ユーザープロフィールページ） |
| 画面 | `ProfilePage`, `ProfileEditPage` |
| データ層 | `UserRepository`, `PostRepository`, `AuthRepository` |

## 2. 画面・コンポーネント構成

| 画面 | 開き方 | 内容 |
|---|---|---|
| ProfilePage（自分） | Map タブ AppBar のアカウントアイコン | アバター（半径 48）・ユーザー名・自己紹介・「プロフィールを編集」・見出し「自分の投稿」・投稿グリッド。AppBar にログアウト |
| ProfilePage（他人） | 投稿者名・コメント主・参加者のタップ | 同上から編集・ログアウトを除き、見出しは「投稿」 |
| ProfileEditPage | 「プロフィールを編集」 | アバター変更（カメラボタン）・ユーザー名（必須）・自己紹介（複数行）・保存 |

投稿グリッドは 5 列で、各マスは先頭画像のサムネイルである。タップで投稿詳細を開く。

## 3. 処理フロー

| 操作 | 処理 |
|---|---|
| 表示 | `watchUser(uid)` と `getUserPosts(uid)` を購読。`userId` 省略時はログイン中ユーザー |
| 投稿一覧 | `posts.where(userId == uid)` を取得し、クライアントで新しい順に並べる（複合インデックス不要） |
| 画像選択 | ギャラリーから 1 枚（最大 800×800・品質 85） |
| 保存 | 画像を選んでいれば `profiles/{uid}/avatar.jpg` にアップロード → `users/{uid}` の username・bio・（画像を選んだときだけ）profileImageUrl を更新 → 前画面へ戻る |
| ログアウト | 確認ダイアログ → `signOut` → `popUntil(isFirst)` で AuthGate まで戻す |

保存中は画面全体の操作を止め（`AbsorbPointer`）、ボタンにスピナーを出す。

## 4. データ設計

`users/{uid}` の username・bio・profileImageUrl を更新する（構造は [01](01_認証・ユーザー登録承認.md)）。プロフィール画像は Storage の `profiles/{uid}/avatar.jpg` に上書き保存する。

## 5. 権限・セキュリティ

| 対象 | ルール |
|---|---|
| `users/{uid}` 更新 | 本人（`approved`・`role` は変更不可）/ 管理者 |
| Storage `profiles/{uid}/**` 書込 | 本人のみ・10MB 未満・`image/*` |

## 6. 入力チェック・エラー処理

| 状況 | メッセージ |
|---|---|
| ユーザー名未入力 | ユーザー名を入力してください |
| 保存成功 / 失敗 | プロフィールを更新しました / 更新に失敗しました |
| UID 取得不可 | ログイン情報が取得できませんでした |
| ユーザー未存在 | プロフィールが見つかりませんでした |

## 7. 既知の制約・課題

- 匿名期間中のコンテスト応募作品は `userId` が空のため、本人のプロフィールにも表示されない（匿名解除後に表示される）。
- プロフィール画像のファイル名が固定のため、URL のトークンが変わらない限り古い画像がキャッシュから表示されうる。
- 自分の投稿一覧は件数制限なしで全件購読する。
- アップロード時の Content-Type は常に `image/jpeg` で、PNG などもその指定で保存される。
