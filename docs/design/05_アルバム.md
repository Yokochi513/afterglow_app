# 05. アルバム

## 1. 概要

投稿をテーマやイベント単位でまとめるアルバムを作る。アルバムは承認済みユーザー全員が閲覧でき、作成者（所有者）だけが編集・削除と投稿の出し入れを行える。アルバムは投稿 ID を参照するだけで、投稿そのものは持たない。

| 項目 | 内容 |
|---|---|
| 関連要件 | PS_02（アルバム作成） |
| 画面 | `AlbumListPage`, `AlbumDetailPage` |
| 部品 | `AlbumEditDialog`, `_AlbumPostPickerDialog` |
| データ層 | `AlbumRepository`, `PostRepository`, `UserRepository` |

## 2. 画面・コンポーネント構成

| 画面 | 内容 |
|---|---|
| AlbumListPage（Album タブ） | 全アルバムを新しい順に表示。各行はカバー画像・タイトル・所有者名・投稿数。FAB で作成 |
| AlbumDetailPage | タイトル・説明・所有者名と、含まれる投稿の 3 列グリッド。タップで投稿詳細 |
| 所有者向け操作 | AppBar の編集・投稿追加・削除。グリッドの長押しでアルバムから外す |
| AlbumEditDialog | タイトル（必須）・説明。作成と編集を兼ねる |
| 投稿選択ダイアログ | 所有者の投稿をチェックボックスで一覧。チェックで即追加、外すと即削除 |

## 3. 処理フロー

| 操作 | サービス呼び出し | 備考 |
|---|---|---|
| 一覧 | `getAlbums()` | `createdAt` 降順で購読 |
| 詳細 | `watchAlbum(id)` → `getPostsByIds(postIds)` | 投稿は ID ごとに個別取得（`whereIn` の 10 件制限を避ける）。削除済み投稿は除外 |
| 作成 | `createAlbum(album)` | ID 自動採番。`ownerId` = 自分 |
| 編集 | `updateAlbum(id, title, description)` | カバー画像は指定時のみ更新 |
| 投稿追加 / 削除 | `addPost` / `removePost` | `arrayUnion` / `arrayRemove` で重複を防ぐ |
| アルバム削除 | `deleteAlbum(id)` | 確認後に削除し一覧へ戻る。投稿は消さない |

## 4. データ設計

`albums/{albumId}`

| フィールド | 型 | 既定値 / 備考 |
|---|---|---|
| ownerId | string | 作成者 UID |
| title | string | 必須 |
| description | string | `''` |
| postIds | string[] | `[]`。並び順 = 追加順 |
| coverImageUrl | string? | null |
| createdAt | Timestamp | 作成時刻 |

## 5. 権限・セキュリティ

| 操作 | ルール |
|---|---|
| 読取 | 承認済みユーザー |
| 作成 | 承認済みかつ `ownerId == 自分` |
| 更新・削除 | 承認済みかつ（所有者 / 管理者） |

UI は `AlbumRepository.isOwnedBy` で所有者向け操作の表示を出し分ける。

## 6. 入力チェック・エラー処理

| 状況 | メッセージ |
|---|---|
| タイトル未入力 | タイトルを入力してください |
| 未ログイン | ログイン情報が取得できませんでした |
| 保存・削除・取り外しの失敗 | 失敗時のみ SnackBar で通知 |

## 7. 既知の制約・課題

- 追加できるのは所有者自身の投稿だけである。
- カバー画像を設定する UI はない（`coverImageUrl` は常に null）。一覧ではプレースホルダーを表示する。
- 投稿を削除しても `postIds` には ID が残る。詳細表示時に除外するだけで、件数表示には含まれる。
- 管理者はルール上他人のアルバムを編集できるが、UI は所有者にしか操作を出さない。
